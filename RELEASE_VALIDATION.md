# Release validation

- 15 CPU unit tests passed: six-task parsing, amount/range errors, prefix idempotence and empty CFG, temporal range, strict patience/reset, detached rollout/corrective target, hybrid loss gradients and metric thresholds/valid denominators.
- All 85,440 published instructions parsed with task IDs matching metadata and amounts matching the one-decimal text tolerance. Evaluation preserves exact numeric metadata rather than parsing rounded text.
- All five data folders: every nonempty audio path resolves to a WAV archive member. Only train publishes paired target audio. All val/test target paths are empty and their archives contain input WAVs only. Complex input member names, sizes, CRCs and compressed payload hashes match the original archives; other split archives retain their original bytes. Metadata changes are limited to stripping instruction prefixes and clearing evaluation target paths; no values are fabricated.
- Original standard FM, k-step objective, sigma sampler and deterministic worker functions retain their original ASTs. Online augmentation algorithms and AudioDataset method bodies match; only portable paths and model-internal prompt wrapping change. Pitch estimators and frozen Selective classification rules are byte-identical to their sources. Retained public metric formulas match their original ASTs.
- All four actual model components strict-loaded on CPU. The selected DiT and actual T5 ran 50 Euler/CFG steps on a small latent. Full 10-second audio passed the actual frontend/VAE/vocoder round trip. This is a component check, not a full-duration end-to-end generation benchmark.
- Every training/inference CLI passed its help/import check. Published files were checked for private host paths, device adapters, credentials and unintended binary training artifacts.
- Existing source files were hash-audited: only the authorized Complex Recovery controller, its k limit/metadata and README changed, plus the new patience helper and inference directory. Historical selected weights/results remain unchanged.

No NVIDIA GPU was available. CUDA execution, distributed training, GPU speed and peak VRAM were not tested. The GPU environment is a specified installation target; memory figures are analytic estimates. The portable training runners adapt orchestration for CUDA while retaining the original scientific helpers and validation rules.
